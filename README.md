# Electronica

Automatically keeps a Spotify playlist stocked with new tracks uploaded to a curated list of electronic music YouTube channels.

## How it works

1. For each channel listed in `config.py`, checks for videos uploaded in the last `SYNC_DAYS` days.
2. Parses each video's title, assuming an `Artist - Title` format, to pull out artist name(s) and track name.
3. Searches Spotify for a matching track for each one found.
4. Replaces the configured Spotify playlist's contents with whatever matches it found.

It's designed to run on a schedule via the included GitHub Actions workflow (`.github/workflows/actions.yml`), currently weekly, and can also be triggered manually from the Actions tab.

## Setup

### 1. Credentials

The script needs the following, provided as environment variables (locally) or GitHub Actions secrets (for the scheduled workflow):

| Variable | What it is | Where to get it |
|---|---|---|
| `YT_API_KEY` | YouTube Data API key | [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Credentials → create an API key, with the YouTube Data API v3 enabled |
| `SP_CLIENT_ID` | Spotify app client ID | [Spotify Developer Dashboard](https://developer.spotify.com/dashboard) → create an app |
| `SP_CLIENT_SECRET` | Spotify app client secret | Same Spotify app, under Settings |
| `REDIRECT_URI` | OAuth redirect URI | Set to whatever you register as a Redirect URI on the Spotify app (e.g. `http://localhost:8888/callback`) |
| `REFRESH_TOKEN` | Spotify OAuth refresh token | Generated by running `get_refresh_token.py` locally - see below |
| `SP_USERNAME` | Your Spotify username | Spotify account settings |
| `PLAYLIST_ID` | The playlist to update | The ID from the playlist's Spotify URL (`open.spotify.com/playlist/<this part>`) |

For the scheduled workflow, add each of these under the repo's **Settings → Secrets and variables → Actions**.

### 2. Getting a refresh token

Spotify refresh tokens expire after 6 months of inactivity, so you'll need to generate one for first-time setup and occasionally regenerate it afterward (`main.py` will tell you when the current one has expired).

With `SP_CLIENT_ID`, `SP_CLIENT_SECRET`, and `REDIRECT_URI` set as environment variables locally:

```bash
python3 get_refresh_token.py
```

This opens Spotify's consent screen in your browser and prints a refresh token to paste into the `REFRESH_TOKEN` secret. It doesn't write anything to disk, so there's nothing produced by this step that needs to be gitignored or cleaned up afterward.

### 3. Configuration

Edit `config.py` to change:
- `CHANNELS` — the dict of YouTube channels to check (name → channel ID; get a channel ID via a [converter tool](https://www.streamweasels.com/tools/youtube-channel-id-and-user-id-convertor/))
- `NO_VIDS_EACH` — how many recent uploads to check per channel
- `SYNC_DAYS` — how far back to look for new uploads
- `MAX_NO` — maximum number of tracks to keep in the playlist
- `MARKET` — Spotify market code used when searching for tracks

## Running locally

```bash
pip install -r requirements.txt
export YT_API_KEY=... SP_CLIENT_ID=... SP_CLIENT_SECRET=... REFRESH_TOKEN=... REDIRECT_URI=... SP_USERNAME=... PLAYLIST_ID=...
python3 main.py
```

## Running tests

```bash
pip install pytest
pytest tests/
```

Tests cover the title-parsing logic in `utils.py` against mocked YouTube/Spotify responses - no real API calls or credentials needed.

## Project structure

```
main.py               orchestration: auth, fetch, search, update playlist
utils.py               title parsing, YouTube fetching, Spotify search logic
config.py              channel list and tuning constants
get_refresh_token.py    one-time Spotify OAuth helper
tests/test_utils.py     pytest suite for utils.py
.github/workflows/      scheduled GitHub Actions run
```

## Known limitations

- Title parsing assumes an `Artist - Title` format and will skip videos that don't roughly follow it (livestreams, announcements, etc.) rather than guess.
- A Spotify search match isn't guaranteed to be correct - it takes the top result for the parsed artist/title query, which can occasionally pick the wrong version of a track (e.g. a different remix) if multiple exist under similar names.
